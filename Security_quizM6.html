Explain security alerting and monitoring concepts and tools.

Monitoring Computing Resources

Effective monitoring covers several layers of an organization's technology environment. Systems monitoring tracks the health and behavior of individual devices, such as servers and workstations. Applications monitoring tracks the performance and security of the software running on those systems, catching issues like unusual access patterns or errors that could indicate a problem. Infrastructure monitoring covers the underlying network and hardware that everything else depends on, such as switches, routers, and cloud resources.

Monitoring Activities

Several activities make up the day-to-day work of monitoring. Log aggregation collects log data from many different sources into a central location, making it easier to search and correlate events across the environment. Alerting notifies security personnel automatically when monitoring tools detect something that matches a defined rule or threshold. Scanning actively checks systems for vulnerabilities, misconfigurations, or malware. Reporting summarizes monitoring data and findings for stakeholders, supporting both day-to-day decisions and long-term planning. Archiving retains historical log and monitoring data for a defined period, which supports investigations and compliance requirements even after the data is no longer actively needed.

Alert response and remediation involves acting on and validating alerts once they are generated. Quarantine isolates an affected system or file to prevent a threat from spreading further while it is investigated. Alert tuning adjusts the rules and thresholds that generate alerts, reducing false positives and ensuring the team's attention stays focused on legitimate threats rather than noise.

Tools

A variety of tools support monitoring activities. The Security Content Automation Protocol (SCAP) is a standardized way to automate vulnerability management and policy compliance checks. Benchmarks provide standardized configuration guidelines, such as those from CIS, that systems can be measured against. Agents and agentless approaches refer to whether monitoring software is installed directly on a device (agent-based) or checks the device remotely without local software (agentless), each with different tradeoffs in visibility and overhead. Security information and event management (SIEM) platforms aggregate and correlate log data from across the environment to detect and alert on potential threats in near real time. Antivirus software detects and blocks known malicious software. Data loss prevention (DLP) tools monitor and restrict the movement of sensitive data to prevent it from leaving the organization improperly. Simple Network Management Protocol (SNMP) traps are automatic alerts sent by network devices when a significant event occurs, without needing to be polled first. NetFlow captures metadata about network traffic patterns, helping identify unusual or suspicious communication between systems. Vulnerability scanners automatically check systems for known weaknesses, tying this section back into the identification methods covered earlier in vulnerability management.

Firewall

Firewalls control traffic entering and leaving a network based on defined criteria. Rules specify what traffic is allowed or denied, typically evaluated in order from most to least specific. Access lists (ACLs) define which specific IP addresses, networks, or users are permitted or denied access. Ports and protocols determine which types of traffic are allowed through, such as blocking unused ports to reduce the attack surface. Screened subnets, often called DMZs, place public-facing systems like web servers on a separate network segment, isolating them from the internal network so that if they are compromised, the attacker doesn't gain direct access to internal resources.

IDS/IPS

Intrusion detection systems (IDS) and intrusion prevention systems (IPS) monitor network traffic for malicious activity, with IPS able to actively block detected threats rather than only alerting on them. Trend-based detection looks for patterns of behavior over time that deviate from the norm, which can catch novel or previously unseen attacks. Signature-based detection compares traffic against a database of known attack patterns, making it fast and reliable against known threats but less effective against new ones.

Web Filter

Web filtering controls what websites and content users can access. Agent-based filtering installs software directly on a device to enforce filtering rules regardless of network location. Centralized proxy filtering routes all web traffic through a central point where filtering rules are applied before traffic reaches the user. URL scanning checks web addresses against known malicious sites before allowing access. Content categorization sorts websites into categories, such as social media or gambling, so policies can be applied by category rather than listing individual sites. Block rules explicitly deny access to specific sites or categories. Reputation-based filtering blocks sites based on a known history of malicious activity, similar to how threat intelligence feeds are used elsewhere in security operations.

Operating System Security

Operating system security tools help enforce configuration and access controls directly at the OS level. Group Policy, used primarily in Windows environments, allows administrators to centrally configure and enforce security settings across many devices at once. SELinux (Security-Enhanced Linux) adds mandatory access controls to Linux systems, restricting what processes and users can do beyond standard file permissions.

Implementation of Secure Protocols

Implementing secure protocols involves several deliberate choices. Protocol selection means choosing secure versions of communication protocols, such as using HTTPS instead of HTTP. Port selection involves configuring services to run on appropriate, often non-default, ports to reduce exposure to automated attacks. Transport method refers to how data is actually carried between systems, and ensuring that method includes encryption so data can't be easily intercepted in transit.

DNS Filtering

DNS filtering blocks access to malicious or unwanted domains at the DNS resolution stage, preventing a user's device from ever connecting to a dangerous site even before a web filter would catch it.

Email Security

Several protocols work together to prevent email spoofing and phishing. Domain-based Message Authentication, Reporting, and Conformance (DMARC) tells receiving mail servers what to do with messages that fail authentication checks, and provides reporting back to the domain owner. DomainKeys Identified Mail (DKIM) adds a digital signature to outgoing email, allowing the receiving server to verify the message wasn't altered in transit. Sender Policy Framework (SPF) specifies which mail servers are authorized to send email on behalf of a domain, helping receiving servers detect spoofed sender addresses. An email gateway sits between the internet and an organization's mail server, filtering spam, malware, and phishing attempts before they reach user inboxes.

File Integrity Monitoring

File integrity monitoring (FIM) tracks changes to critical files and system configurations, alerting administrators when unauthorized or unexpected modifications occur, which can indicate a compromise or misconfiguration.

Data Loss Prevention (DLP)

Data loss prevention (DLP) tools monitor, detect, and block sensitive data from leaving the organization improperly, whether through email, removable media, or cloud uploads, helping prevent both accidental leaks and intentional data theft.

Network Access Control (NAC)

Network access control (NAC) verifies that a device meets security requirements, such as having up-to-date antivirus or patches, before allowing it to connect to the network, helping prevent unsecured or compromised devices from gaining access.

EDR/XDR

Endpoint detection and response (EDR) monitors individual devices for suspicious activity and can respond automatically, such as isolating a compromised endpoint. Extended detection and response (XDR) expands on this by correlating data across endpoints, networks, and other sources for broader visibility into an attack that might span multiple systems.

User Behavior Analytics

User behavior analytics (UBA) establishes a baseline of normal user activity and then flags deviations from that baseline, such as a user suddenly accessing systems or data they never have before, which can indicate a compromised account or insider threat.

Explain appropiate incident response activities.

Incident response typically follows a defined set of phases. Preparation involves establishing the plans, tools, and training needed before an incident occurs, so the team isn't figuring things out for the first time during a real event. Detection involves identifying that a security incident may be occurring, often through monitoring tools or user reports. Analysis involves investigating the detected activity to confirm it is a genuine incident and understand its scope and impact. Containment involves limiting the spread of the incident to prevent further damage, such as isolating an affected system. Eradication involves removing the root cause of the incident, such as deleting malware or closing the vulnerability that was exploited. Recovery involves restoring affected systems and services back to normal operation. Lessons learned involves reviewing the incident afterward to identify what worked, what didn't, and what changes should be made to prevent a similar incident in the future.

Training

Training ensures that everyone involved in incident response, from technical staff to leadership, understands their role and responsibilities before an actual incident occurs, reducing confusion and delays when a real event happens.

Testing

Testing validates that an incident response plan actually works in practice. A tabletop exercise is a discussion-based session where participants walk through how they would respond to a hypothetical scenario, without actually taking real technical action. A simulation goes a step further by actually carrying out response actions in a controlled environment, providing a more realistic test of the plan and the team's readiness.

Root Cause Analysis

Root cause analysis identifies the underlying reason an incident occurred, rather than just addressing its immediate symptoms, so the organization can fix the actual weakness and prevent the same type of incident from happening again.

Threat Hunting

Threat hunting involves proactively searching for signs of malicious activity that may have gone undetected by automated tools, rather than waiting for an alert to trigger. This assumes that some threats may already be present in the environment and looks for subtle indicators that confirm or rule that out.

Digital Forensics

Digital forensics involves collecting and analyzing digital evidence in a way that preserves its integrity and legal validity. A legal hold requires preserving relevant data because it may be needed for litigation or investigation, preventing it from being deleted or altered in the normal course of business. Chain of custody documents who has handled evidence and when, from collection through final use, ensuring it can be trusted and admissible if needed for legal proceedings. Acquisition is the process of collecting evidence, such as creating a forensic image of a hard drive, in a way that doesn't alter the original data. Reporting documents the findings of a forensic investigation in a clear, defensible format. Preservation ensures evidence remains unaltered and protected from damage or loss throughout the investigation. E-discovery refers to the process of identifying, collecting, and producing electronic evidence in response to a legal request, such as during litigation.

Types of Security Controls

Organizations use several layers of security controls to reduce cyber risk. No single control can stop every attack, so companies combine multiple approaches to create a strong defense.

Control Type Examples Purpose
Technical Firewalls, Antivirus, Encryption, MFA Protect systems using technology.
Managerial Security Policies, Risk Assessments, Audits Guide security planning and governance.
Operational Security Awareness Training, Incident Response Improve daily security procedures.
Physical Badge Readers, Cameras, Locks, Biometrics Protect facilities and equipment.
Defense in Depth

Good cybersecurity relies on multiple layers of protection rather than a single security solution.

Cryptography and Public Key Infrastructure (PKI)

Encryption protects sensitive information by converting readable data into an unreadable format that only authorized users can access.

One of the most widely used cryptographic systems is Public Key Infrastructure (PKI), which uses two mathematically related keys.

Key Purpose
Public Key Encrypts data and verifies digital signatures. It can be shared freely.
Private Key Decrypts encrypted data and creates digital signatures. It must remain secret.
Common PKI Technologies
  • Digital Certificates
  • Certificate Authorities (CA)
  • Hardware Security Modules (HSM)
  • Trusted Platform Modules (TPM)

PKI helps secure websites, email communication, VPN connections, software updates, and many other everyday technologies.

Change Management

Every modification to software, hardware, or network infrastructure should follow a formal change management process.

Proper planning reduces downtime, prevents configuration mistakes, and minimizes security risks caused by unauthorized or poorly tested changes.

Step Description
Request Document the proposed change.
Review Assess security and business impact.
Approval Receive management authorization.
Implementation Deploy the approved change.
Verification Confirm the change was successful.
Documentation Record the completed work.
Why It Matters

Structured change management improves security, accountability, system stability, and compliance.
